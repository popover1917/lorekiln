# Collaborative Experience Analysis

Use a divergent-then-convergent review:

1. **Context reconstruction** — inspect the selected anchors and relevant artifacts before asking the
   user to repeat known facts.
2. **Fact table** — separate direct observations, user corrections, outcomes, and unresolved gaps.
3. **Classification** — group by domain and distinguish preference, method, failure pattern,
   environmental constraint, and hypothesis.
4. **Divergent brainstorming** — generate two or more plausible interpretations when evidence admits
   alternatives; apply YAGNI to avoid inventing elaborate systems for isolated incidents.
5. **Adversarial check** — search for counterexamples, scope limits, conflicting instructions, and
   simpler explanations.
6. **Convergence** — recommend the smallest durable lesson that the evidence supports.
7. **Joint review** — show evidence and uncertainty, invite technical correction, and retain only
   conclusions the user accepts for candidate storage.
8. **Verification** — require fresh tests or observable outcomes before claiming that a promoted
   capability improved.

These principles adapt useful parts of `obra/superpowers`: project-context-first brainstorming,
multiple approaches with trade-offs, clear component boundaries, root-cause investigation,
technical review over performative agreement, and evidence before completion claims.

Do not copy its platform-specific skill chaining or make brainstorming mandatory for unrelated
memory capture. Mechanical capture must remain deterministic and model-free.
